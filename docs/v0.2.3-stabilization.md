# v0.2.3: exact-file language fallback and bounded library enumeration

Approved v0.2.3 stabilization based on v0.2.2. Historical release tags and images remain unchanged. All fixtures are generated or mocked; no live media or production services are used.

## Language evidence

The previous client schemas discarded `languages` on episode/movie files, and the scanner decided solely from normalized ffprobe language tags. An undefined stream therefore remained needs-analysis even when the exact file was classified as English in Arr.

Both current API v3 file resources expose `languages: [{ id, name }]`. Sonarr associates episode `episodeFileId` with episode-file `id` and `seriesId`; the episode's `seriesId` must also match. Radarr associates movie-file `movieId` with movie `id`. A nested Radarr `movieFile` can supply the same evidence without a second HTTP request. We do not infer file language from series/movie original language, release names, or custom-format names such as “english”. Those are not proof of a stream's language.

The normal explicitly tagged required-language decision runs first and is unchanged. Fallback requires:

- A valid inspected program duration and exactly one eligible unknown-language candidate.
- A default track, or the only audio track in the file.
- No commentary/bonus indication, forced flag, short track, or unaccepted descriptive audio. Existing track flags and title detection remain effective.
- A genuinely missing/undefined language tag (missing, `und`, `unknown`, `undefined`), not an unrecognized explicit tag that normalization happens to map to `und`.
- No explicit language contradiction in eligible main-program audio.
- Exactly one useful Arr file-language classification, matching a required language.
- Matching source, entity ID, file ID and Arr path, plus the approved local path mapping.

Multilingual Arr classifications and multiple plausible tracks remain unresolved. An explicit non-required main language retains the existing failure behavior; an unknown track alongside contradictory main audio remains needs-analysis. File-level language is corroboration, not proof of a track assignment.

Library/title/season/rescan audits retain compact exact-file language evidence and pass it into ffprobe classification. Unassociated raw-path/file or webhook inspections remain conservative rather than using unverified/stale library metadata. No language-only per-file HTTP requests are introduced during enumeration.

Scan evidence stores the original normalized/raw ffprobe language, source (`sonarr-fallback` or `radarr-fallback`), file identity/languages, selected track and default/commentary/descriptive flags. History shows a compact explanation; detailed JSON remains expandable. ffprobe track language itself is never rewritten to English.

Cached scans are reused only when current exact-file Arr evidence also matches. The inspection revision invalidates old decision caches; file-integrity checks used by quarantine/remediation remain separate and intact. A passing library rescan resolves an open “unknown language” attention entry for that media, without clearing unrelated operational attention or deleting history.

## Large libraries

The previous transport collected the complete JSON response into buffers and rejected responses above 4,000,000 bytes. API v3 `/movie` and `/series` are unpaged lists; supplying invented page parameters would silently repeat the same list. Sonarr episode/file queries are already scoped by series; Radarr file queries support movie scope.

The alternative is a bounded incremental JSON array reader, used only by library list methods. It parses one record, validates/project-selects needed fields, and discards plots/images/custom-format payloads before the next record. It does not concatenate the full response or retain raw Arr payloads. Independent limits are:

| Boundary | Limit |
| --- | --- |
| Library-list response wire bytes | 64,000,000 |
| One JSON object | 128,000 UTF-16 code units |
| JSON nesting | 64 |
| Records in one response | 100,000 |
| Retained projected metadata per response | 16,000,000 JSON bytes |
| Retained file inventory per source | 16,000,000 JSON bytes |
| Files in combined audit | 100,000 |
| Library HTTP idle / total deadline | 8 seconds / 60 seconds |
| DNS deadline | 8 seconds |
| Other buffered API responses | unchanged 4,000,000 bytes / 8 seconds |

The compact inventory is still retained for stable job totals, but is explicitly bounded; it is not the enormous original Arr dataset. Two-source audits can retain up to two bounded inventories plus the active source's compact lists and parser working data. These are serialized-size limits, not a promise of an exact process RSS ceiling. The parser consumes one network chunk and one capped record at a time. No new runtime dependency is required.

Sonarr and Radarr share this protection. Scoped series/movie audits use single-resource endpoints and the existing ordinary-response limit instead of downloading the full catalog. Sonarr continues per-series episode/file queries. Radarr reuses its embedded exact movie-file resource when available; otherwise it queries that movie's files. Identical duplicate records collapse; conflicting identities fail closed. Multi-episode files retain each distinct episode association.

Abort signals reach active HTTP requests. DNS pinning, mixed-address SSRF rejection, TLS validation, no redirects, API-key headers, URL-base joining and safe errors are preserved. The worker validates service identity before enumeration, retains lease/retry behavior, and reports discovered-file counts during enumeration. No mutation is made to Arr or media.

A response that exceeds the new finite limits still fails clearly. Select a specific series/movie audit to bypass an oversized unpaged catalog. There is no unlimited-library claim and no configurable “disable limits” switch.

## Job wording

Exhausted job retries and expired final leases now end in `failed`, displayed as “Scan failed”. A zero-processed failed job explicitly says no media inspection completed. Historical zero-processed scan jobs recorded as needs-attention are labeled as scan/setup failures. Item-level attention remains distinct. Failed jobs do not falsely acquire 100% completion; cancellation and lease ownership behavior are unchanged.

## Regression coverage

- Normal English, Sonarr/Radarr fallback, commentary/title/bonus/forced/short/descriptive negatives, contradictory explicit language, missing/multilingual metadata, ambiguous tracks, unknown explicit tags, and wrong entity/file/path/source.
- Actual generated AC3 stereo default `und` Matroska fixture inspected by production ffprobe; no real Rugrats file is accessed.
- Real authenticated HTTP mock libraries with 600 titles and more than 4 MB of JSON each. The old ordinary transport is explicitly shown to reject the same payload. First/last records, unique identities, compact output, base paths and no Radarr per-file language requests are asserted.
- Active cancellation, stalled-response timeout, authentication and path errors, malformed/truncated JSON, UTF-8 chunk boundaries, escaped delimiters, record/total/count/nesting/retained-output limits and streaming SSRF rejection.
- Real worker/cache/SQLite test changes Arr evidence without changing the media, proving reassessment and narrowly scoped attention resolution.
- Existing production Unraid gate now uses generated `und` AC3 and exact English classifications; both sources must pass and show fallback evidence after fresh setup, restart, recreation and original-key restoration. Wrong-key failure, non-root health, unchanged read-only media and all previous connection/security tests remain enabled.

## Compatibility and release

No database migration, dependency change, new Unraid variable or setting is required. Existing v0.2.2 encrypted credentials, settings and database remain compatible. Keep the same `/config`, encryption key, identity settings and read-only media mounts. After upgrading, rerun affected library/title audits to obtain new evidence. Old history is retained.

v0.2.3 contains only this conservative language fallback, bounded enumeration, evidence presentation and scan-failure wording, with their regression coverage. Limits and ambiguous cases above remain deliberate.
