# v0.1 audit and v0.2 remediation

The original v0.1 release was a Monitor Only proof of concept. Its principal gaps were unauthenticated administration, one-line maintainability-hostile source modules, no encryption or secret persistence model, static setup screens, no mapping CRUD, synchronous scans, a minimal migration marker, and a release workflow that published before validation.

v0.2 introduces a versioned SQLite migration ledger which preserves v0.1 settings, scans, events, and rejection rows; local administrator authentication; hashed sessions; CSRF and exact origin enforcement for write endpoints; mappings; persistent job records; and pre-publication CI/release checks. Existing v0.1 databases migrate in place: tables are additive and v0.1 records are retained.

The following are still deferred and must not be assumed: encrypted Arr credential storage, branding asset upload UI, Arr library enumeration, recurring worker recovery, quarantine/restore, automatic blocklisting/replacement, browser E2E tests, and an AI speech detector. These are deliberately not exposed as functioning features.

## Rollback

Back up `/config` before upgrading. v0.1 can read its original settings/scans/events tables after a v0.2 upgrade, but it will ignore new tables. Downgrade only after stopping the container and preserving a copy of the v0.2 database.
