# v0.1 audit and v0.2 remediation

The original v0.1 release was a Monitor Only proof of concept. Its principal gaps were unauthenticated administration, one-line maintainability-hostile source modules, no encryption or secret persistence model, static setup screens, no mapping CRUD, synchronous scans, a minimal migration marker, and a release workflow that published before validation.

v0.2 introduces a versioned SQLite migration ledger which preserves v0.1 settings, scans, events, and rejection rows; local administrator authentication; hashed sessions; CSRF and exact origin enforcement for write endpoints; mappings; persistent job records; and pre-publication CI/release checks. Existing v0.1 databases migrate in place: tables are additive and v0.1 records are retained.

The development branch now includes encrypted Arr settings, branding uploads, Arr enumeration, a leased worker, quarantine/restore, mock-validated automatic remediation, and browser E2E tests. This is not a declaration that v0.2.0 is release-ready. See `V0.2.0-TODO.md` for the remaining product/release work and `interrupted-work-review.md` for the safety-commit review. Speech detection remains an optional code-level interface, not an installed or worker-integrated model.

## Rollback

Back up `/config` before upgrading and preserve the encryption key separately. Do not point v0.1 at a migrated v0.2 database: restore the pre-upgrade v0.1 config backup when rolling back, after stopping the container and preserving a separate copy of the v0.2 config. The immutable v0.1 image/tag is unchanged.
